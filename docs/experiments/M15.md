## Runs

- RUN: 15 tests (the two views) were red before the models existed, then 15/15 green after a fixture misuse in one test was fixed (`plan: null` falls back to the real plan, so the test now uses `drop`); full suite 271/271.
- BROWSER: see G3 (`tests/walkthrough/g3-browser.py`, 42 checks): the whole journey by keyboard, leaving and coming back, the configuration change, focus at every stop, 320 px.
- Measured: no target under 24 px in My health, My plan, On board, My day, Habitat or My progress; My day's links were 20 px and were fixed.

## Negative controls

Scratchpad `mutate-f3b.mjs`: 12 controls, each red: start offered when blocked (P1), configuration ignored (P2), resume at step 0 (P3), review status hidden (P4), result shown as "fine" (P5), not-done tasks hidden (P6), done never links the execution (X1), Finish always enabled (X2), read-only ignored for start (X3) and for marking (X3b), version text from the current procedure (X4), task availability ignores the configuration (X2b). Two controls were **equivalent mutants**, not run: dropping the view's own blank-reason checks changes nothing because `plan.mark` and `procedures.finish` refuse the same input (two doors).

## Refuted and surprises

Browser control C3 (an interrupted execution gains an Advance action) was **not caught by the browser walk**; the model test M15-P3 catches it. One test was wrong, not the code (see Runs).

## Addendum — On board reads the registry, and a minimal editor

Predictions written before the code: M15-E1 a procedure written here is published as a draft with source `user_entered`, never as reviewed; M15-E2 changing an existing procedure publishes its next version and leaves the old one and its executions alone; M15-E3 an invalid form is refused in words and stores nothing; M15-E4 a read-only source cannot publish. M15-X4 was rewritten: after a newer version is really published, an execution still reads its own version's step text (before, it said the text was "not available here").

Runs: 4 new tests plus the rewritten X4, 280/280 at that point; the editor is walked by keyboard in `tests/walkthrough/g4-browser.py` (open the form, type, publish, refusal as an alert, pick an existing procedure to prefill, publish version 2). Controls E1, E2, E3, E4 and X4 go red; browser control C2 (published as reviewed) goes red.

Not verified: no way to delete or retire a procedure (versions only accumulate); the editor has no step reordering; a written procedure is checked only for shape (500 characters per text, 50 items), not for content. It is a draft by construction and the screen says so.
