## Interpretation decisions (not contract changes)

- **D-M07-1 Collaborators are injected.** `modules.csv` gives M07 only M00 as a dependency, so the base components and the shell model import no other module. `app/ui/base/start.js`, loaded by `app/index.html`, is the one composition root: it alone imports store, scenario and readings, loads the view modules and hands everything to the shell. (The first draft of this record named index.html as the root; the code put it in `start.js` to keep the HTML a plain entry point.)
- **D-M07-2 Freshness is data.** "Old" needs a cutoff, and the module may not hold one. `dataStateBadge` takes `old_after_days` from its context; a view must supply it with its own source. Without it the badge shows the age only. This is a request to the orchestrator: where should the freshness rule live (configuration, catalog or view)?
- **D-M07-3 Component shapes.** CONTRACTS.md leaves argument lists to M07: `stateLabel(recordOrState)`, `originLabel(origin)`, `valueWithContext(record, { clock })`, `accessibleTable({ caption, columns, rows })`, `lineChart(seriesResult, { unit, label })`, `dataStateBadge(record, { clock, old_after_days, comparable, reason })`, `attentionBadge(result)`. Drawing is a plain tree of `{ tag, attrs, text, children }` rendered by `dom.js`, so Node can test it and no record text goes through `innerHTML`.
- **D-M07-4 Gap wording.** A day with no entry and a day marked not recorded both read "not recorded" (the entry-less one adds "no entry for this day"), because P2 requires that wording and both are absence. Neither is ever drawn or worded as zero or as "nothing new".
- **D-M07-5 The G0 browser script is not mine.** `tests/walkthrough/g0-browser.py` asserts the M00 text. The new shell keeps `html[data-modules="loaded"]` and a `#status` line with the contract version so that script's assertions stay meaningful.

## Addendum 2 — time-of-day charts: predictions written before the run

`lineChart(series, { unit, label, resolution: "time", day, sampling })` draws one day by time of day. `resolution` defaults to `"day"`, which keeps every behaviour above. Lines join two consecutive readings only when a sampling interval is given as data with its source. Written before the code.

**D-M07-7 DOM renderers are part of the single door (added with M22, contract 0.11).** `ui/base/index.js` now also exports `renderChart`, `renderTable` and `renderBadge`, because a view cannot draw the chart and table models without importing a file inside this module. The M07 Node suite (25 of 25) and browser check (22 of 22) still pass. Shared styles for fields, cards, definition lists, the submit button and citations were added to `style.css` after looking at M22's first screenshots.

**D-M07-6, a reviewable choice:** a reading counts as missed when the next one arrives later than 1.5 sampling intervals. That is the midpoint between "the next reading" (1 interval) and "one reading missed" (2 intervals). It is a rule about sampling geometry, not a health value; the interval itself always comes from the caller with its source.

## Addendum 3 — measured accessibility, reflow and layout

**Skills.** Read before this work: `frontend-accessibility-by-construction` (the full body, including its checklist and the WCAG 1.4.3 / 1.4.11 / 2.5.8 thresholds it states) and `frontend-performance-budgets` (for the reference figures used under M22). **Process admission:** `app/ui/base/quality-check.py` was written and run before its predictions were written down, so the first run is recorded as an observation, not as a confirmed prediction. The predictions it then tested, with the thresholds WCAG 2.2 states: text contrast of at least 4.5:1 (3:1 for large text); control borders, the focus outline and the chart's marks at least 3:1 against their background; no horizontal page scroll at a 320 CSS px viewport (data tables may scroll inside their own region); links, buttons and fields at least 24x24 CSS px; an accessible name on every link, button, field, checkbox, select and image, read from Chromium's accessibility tree; heading levels that do not skip.

**First run, on the unfixed code (BROWSER, Chrome for Testing 153.0.8010.12, real BUT CGM, MR079G, MR035G and MR080G files loaded in the NASA view, light and dark, 1100, 390 and 320 px): 46 failures.** Text passed everywhere (lowest contrast 6.29:1 light and 8.23:1 dark over 505 text elements) and so did the focus outline (6.8:1 and 12.9:1). What failed: control borders at 2.90:1 (2.65:1 on a panel) in the light scheme and 2.12:1 in the dark one; the file input was 21 px high; and at 390 and 320 px the page scrolled horizontally by 193 and 263 px because of the configuration select (long option text), the definition list holding the licence URL, and wide tables. These are defects I could not have known about without measuring.

**Fixes.** A `--control-border` token (`#7c8fa8` dark, `#5f6f85` light); a minimum height for the file input; `min-width: 0` and flex sizing on the configuration select; `overflow-wrap` rules; and `renderTable` now wraps the table in a named, keyboard-reachable scroll region (contract 0.11 wording updated).

**A regression I introduced, found by looking and not by the script.** My first wrapping rule (`overflow-wrap: anywhere` on table cells) let a column shrink to one character, so "4.24 %" broke over three lines and the header read "Va / lue". The script passed; a screenshot at 390 px showed it. The rule is now `break-word` for cells. The script has no check for broken words, so this class of defect stays visible only to the eye.

**After the fixes:** 0 failures in the six views; 26 controls named per view; headings in order; no horizontal scroll at 320 px. The script was seen failing 46 times on the unfixed code, which is its negative control.

**Not verified.** No screen reader was run; the accessibility tree was read, not listened to. Firefox and WebKit are not installed here (`/opt/pw-browsers` holds only Chromium), so only Chromium was measured. High-contrast mode, text-spacing overrides and zoom levels were not tried. The 320 px check proves no horizontal page scroll, not that the narrow layout is pleasant (only one narrow screenshot was looked at).

## Refuted and surprises

- **No prediction from the work order was refuted.**
- **Surprise 1: the X8 tripwire fired on the first green run** (`shell-model.js: ok`). Rival explanations: (a) a label that says "ok"; (b) the property name `ok` of a `Result`. Reading the line settled it: `ownValue(result, 'ok')`, a property name. The module was changed to read `result.ok` directly so the scan stays strict (no exemption list), because a label "ok" must still be caught.
- **Surprise 2: one negative control was not caught.** Removing the caption check left every test green. Cause: my test used `columns: []` in the same input, so the table was refused for another reason. This is a finding about my test, not a refuted prediction. The test now has three inputs with valid columns and no caption and asserts `error.field === "caption"`; the control then went red.
- **Surprise 3: a 404 console error in the real page.** Rivals: (a) a missing module; (b) the favicon request Chromium makes unasked. Cheapest discriminator: record failing responses (none were reported, which fits a browser-internal favicon fetch) and add `<link rel="icon" href="data:,">` to `index.html`. The error disappeared, so (b) held. No icon file was added.
- **Surprise 4: `file://` opened here.** `docs/experiments/E00` and the G0 script recorded it as blocked by managed policy in an earlier environment. In this one the page opened, the notice stayed and no module ran. Environment-specific; the earlier record is not corrected, only supplemented.
- **Observation: the X9 browser control was caught by an earlier check** (the `href` list), so the Tab/focus checks were not shown red by that breakage on their own.
- **Surprise (addendum 2): the browser script broke on itself.** Adding a third chart made the earlier `.legend` locator match two elements. Rival explanations: the legend was not rendered, or the locator was ambiguous. The error ("waiting for locator('.legend')") and the count of charts pointed to the second; scoping it to `#probe .legend` made all 22 checks pass, with no product change. Chromium's own background calls to www.google.com were refused by the network proxy during that run; they are not product traffic.
