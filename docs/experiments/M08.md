## Decision details

| Decision | Alternative rejected | Reversibility | Revisit when |
|---|---|---|---|
| Rest kinds come from a small data table keyed by `method` (scheduled rest, sleep self-report, estimated sleep); an unknown method is shown by its own name | Inferring the kind from the value or the time; merging by variable | Two-way | A catalog of methods exists |
| Writing is enabled only for a writable source with `core` and `newId` | Letting any source write | Two-way | The origin of real entries is decided (the user's call) |
| "Nothing new" is a `confirmed_none` observation of variable `other`, method `self_report` | A new variable; a `recorded` zero | Two-way | The copilot's observation catalog is built (F4) |

## Runs

- RUN: `node --test app/ui/my-health/my-health.test.js` was red against the stub (every test failed), then 8/8 green after the model. Full suite 230/230 at this commit.
- BROWSER (Chromium 153, `tests/walkthrough/g2-browser.py`): nothing-new button by keyboard gives "Saved: nothing new, confirmed." and keeps focus; an empty value is refused with an alert and the chosen variable is kept; typing 88 saves and the view then shows 88 bpm.
- Saving goes through `core.createRecord` and `store.save`; nothing is written when the source is not writable (M08-X3).

## Negative controls

Scratchpad `mutate-views.mjs`: P1 (rest merged), P3 (nothing new saved as a recorded 0), X3 (writable ignored), X4 (score field) each turn their named test red. **M08-X2 (drop the view's own finite-number check) stayed green: an equivalent mutant**, because `core.createRecord` independently refuses NaN and Infinity (RUN: both return `Invalid or missing field value`). Two doors defend the same path.
